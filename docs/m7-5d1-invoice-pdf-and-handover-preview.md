## 1. Proposed document flow (before implementation)

Reuse the existing M7.5B preview RPC and delivery-note print pattern (`window.print()` + `print:hidden` chrome). Do not give drivers invoice-note permission (they still have only `deliveries.execute`). Godown managers print a **driver copy** for paper handover. Accounts (or GM with prepare) open a **financial preview copy** only for reviewed notes.

Two presentations, one RPC: `get_invoice_note_preview(note_id, copy)`.

`recipient` / `transporter` remain driver-family aliases so M7.5B/C.2 HTTP keep working.

PDF is a **separate download** generated from the same RPC payload (`jspdf` + `jspdf-autotable`). Browser Print → Save as PDF is not treated as that download.

## 2. Architecture

| Layer | Behaviour |
|---|---|
| RPC `get_invoice_note_preview` | STABLE SECURITY DEFINER. No writes. |
| Driver family | Quantities from `invoice_note_lines`. Prices, GST, tax IDs stripped. |
| Accounts family | Requires `invoice_notes.prepare` or `invoices.review`, and `status = reviewed`. Prices from note line snapshots. Tax from `get_invoice_tax_preview` snapshot or explicit unavailable/stale. |
| UI `/invoices/:id/preview` | Chooser, then `?copy=driver` or `?copy=accounts`. |
| Print | A4 portrait CSS, repeating table headers, print-stable watermark. |
| PDF | Client file from the RPC JSON. Filename `{note_number}-{family}-preview.pdf`. |

Viewing or printing does not call dispatch, delivery, or stock writers.

## 5. Print and PDF

- **Print A4** opens the browser print dialog for the HTML document. `@page { size: A4 portrait; margin: 12mm }`. Watermark uses `print-color-adjust: exact`.
- **Download PDF** writes a real `application/pdf` file from the snapshot payload. It is not the print dialog.

jsPDF Helvetica cannot draw `₹`, so PDF amounts are labelled `INR …`. On-screen amounts still use `formatInr`.

Playwright can assert the download filename. It does not parse PDF page operators in Chromium here. Vitest inspects generated bytes for `%PDF` and `NOT A TAX INVOICE`, and checks `/Count` > 1 for a 48-line table.

## 8. Limitations

- Chromium e2e asserts the PDF download filename. It does not decode PDF content streams. Byte-level watermark and page-count proof is Vitest.
- `jspdf` pulls `html2canvas` into the preview chunk. Justified: no existing PDF library, and the requirement asks for a downloadable PDF distinct from print.
- Accounts copy with a current calculated GST snapshot still depends on C.2 `preview_invoice_tax`. D.1 HTTP proves missing and stale states without inventing totals.
- Driver paper handover is printed by GM/Accounts. Drivers do not receive in-app financial screens.
